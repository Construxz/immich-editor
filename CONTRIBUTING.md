# Contributing

Thanks for helping. This is a small project run by one person, so a little structure keeps it
manageable.

## Reporting a bug

Open an issue with the **Bug report** form. Please fill in your phone model, Android version,
app version (shown in the account screen) and the steps that lead to the bug. Screenshots help.
If the bug is about a specific photo, say what kind it is (HDR, RAW, from which camera), and
share the photo only if you are fine with it being public. **Remove GPS data and other personal
details first.**

## Suggesting a feature

Open an issue with the **Feature request** form. Tell us what you want to do and why, not only
how. The current plan is in [docs/ROADMAP.en.md](docs/ROADMAP.en.md) (German original:
[docs/ROADMAP.md](docs/ROADMAP.md)).

## Pull requests

- **Small fixes** (typos, an obvious bug) can go straight to a pull request.
- **Anything bigger: open an issue first**, so we can agree on the approach before you put time
  into it. A PR that arrives unannounced and changes a lot may be closed.
- CI (format, analyze, tests) has to pass. For a first-time contributor it starts once the
  maintainer approves the run.
- By contributing, you agree that your contribution is licensed under [AGPL-3.0](LICENSE).

## AI-assisted contributions

This project is itself written with an AI coding agent (see the README), so AI help is
**welcome** here, unlike in Immich. We only ask for three things:

1. **Say so.** Mention in the PR or issue which tool you used and for what.
2. **Test it yourself.** Run it on a real device or the emulator and describe what you checked.
   "The model says it works" is not a test.
3. **Understand it.** You should be able to answer questions about your change. Unreviewed
   generated code, mass-produced issues and issues filled with generated text will be closed.

## Documentation

The project docs are in German (an English translation is planned). If you are not comfortable
writing German, write in English and we will take care of the rest.
